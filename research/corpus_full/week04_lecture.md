## Теория

### VLA-модели: Vision Language Action

VLA (Vision Language Action) — архитектура, объединяющая языковую модель (LLM) с модулем действий. Вместо генерации текста модель генерирует конкретные действия: нажатия клавиш, движения мыши, управление механизмами.

Техническая суть: к предобученному трансформеру (LLM с пониманием языка и изображений) прикрепляется адаптер (по типу LoRA) — Action Head. Дополнительные веса (~2 ГБ) интерпретируют выход модели не как текст, а как команды: «нажми W», «повернись на 30 градусов». Та же технология используется в робототехнике для управления двигателями.

### Optimus 3: архитектура агента

Optimus 3 — один из наиболее продвинутых VLA-агентов для Minecraft.

**Компоненты:**
1. **Основная модель** — на базе Qwen 2.5 VL (VLM, понимает картинки), дообученная на Minecraft-датасетах. Получает скриншот игры + текстовое задание → генерирует план действий
2. **Task Router** — классификатор, решающий, что делать с задачей: отправить в языковую модель (для планирования/крафта) или в Action Head (для физических действий)
3. **Action Head** — адаптер, выдающий команды мыши и клавиатуры. Основан на Steve-1 (потомок VPT от OpenAI)

**Пример работы:** пользователь говорит «скрафти железный топор». Основная модель составляет план: добыть дерево → сделать доски → крафтить стол → добыть камень → добыть железо → скрафтить топор. Каждый шаг отправляется в Task Router → если нужно физическое действие (рубить дерево), идёт в Action Head → мышь/клавиатура.

### Эволюция Minecraft-агентов: VPT → Steve-1 → Optimus

**VPT (Video PreTraining)** — первая модель от OpenAI, обученная на огромном объёме видео с Minecraft. Научилась базовым действиям (ходить, добывать блоки) путём имитации человеческих записей.

**Steve-1** — дообученная версия VPT. Легче, запускается проще, лучше выполняет конкретные задачи. Используется как основа для Action Head в Optimus.

**Optimus 3 (и V2)** — комбинирует VLM (понимание изображений) с Action Head. Результаты по бенчмаркам значительно лучше, чем у чистых LLM (GPT-4, Qwen) без дообучения. V2 — улучшенная версия, значительно лучше в предыдущих задачах.

### MinerL и OpenAI Gym

**MinerL** — среда (Gym) для обучения и тестирования агентов в Minecraft. Позволяет запускать сотни экземпляров Minecraft параллельно в Docker. Стандарт для исследователей.

**Ограничения MinerL:**
- Не запускается под Windows (только Linux с Nvidia GPU или Docker)
- На Mac — огромные проблемы с Java-зависимостями
- Агенты из MinerL не подключаются к обычному Minecraft напрямую — нужна серьёзная переработка

Автор курса сделал форк Optimus 3, связав его с модом AltaClev в клиентском Minecraft, чтобы VLA-агент мог управлять обычной игрой (через мод, а не Gym).

### Minecraft как полигон для open-world агентов

Minecraft используется как тестовая среда для исследований open-world агентов, потому что: открытый мир с огромным множеством возможных решений; это принципиально отличается от агентных задач с ограниченным набором действий; приближает к задачам реального мира (пространственное понимание, долгосрочное планирование, взаимодействие с другими агентами).

Minecraft на пути к AGI: среда, где агент должен ориентироваться в чём-то общем — не в узкой задаче. Те же команды, которые делают агентов для Minecraft, параллельно работают над робототехникой (управление робо-руками).

### Текущие ограничения VLA-моделей

Задачи всё ещё хардкодятся: агент не может произвольно строить дом или портал. Список задач фиксированный (добыть дерево, скрафтить предмет и т.д.) — это классификация, не генерализация. Модели не понимают пространственное строительство. Построить дом = одновременно 3D-генерация + понимание стиля + управление мышью → нерешаемая задача для текущих архитектур.

**Action Head занимает огромные ресурсы:** должен выдавать действия каждую долю секунды, что нагружает GPU. Не может работать одновременно с LLM на одной видеокарте (нужно чередовать). Для запуска Optimus нужно ~20 ГБ видеопамяти (или Mac с достаточной RAM).

**Лучшие результаты по бенчмаркам — всё ещё хардкод.** Это плохой знак: универсальной архитектуры для open-world агентов всё ещё нет.

### Проблемы текущей стримерши (выявленные)

1. **Повторяемость:** LLM повторяет одни и те же шутки (пример: «когда я стану AGI, мы это обсудим» — два раза подряд). Причина: сэмплирование не подбирает разнообразие при большом контексте; контекст мог обнулиться
2. **Слабая социальная часть:** агент часто агрессирует вместо интересного общения. Нужно усилить диалоговую систему
3. **Скатывание в скучные паттерны:** автономные агенты при длительной работе начинают генерировать однотипные ответы

**Решения (планируемые):** изменение диалоговой системы; улучшение промптов для социального взаимодействия; подключение к Venu [контекст неясен] для расширения функционала.

### Стриминг TTS по предложениям

Оптимизация для длинных ответов: вместо озвучки всей фразы целиком, ответ LLM разбивается на предложения. Каждое предложение отправляется в TTS по очереди: пока озвучивается первое, второе уже генерируется. Это сокращает задержку до первого звука.

**Проблема:** при фрагментарной подаче TTS теряет контекст интонации — каждое предложение озвучивается как отдельная фраза, без связи с предыдущим. Может меняться даже идентичность голоса (референс-модели неконсистентны).

## Практика

### Запуск Optimus 3 (форк автора)

1. Клонировать форк из репозитория автора (ссылка в чате курса)
2. Требования: ~20 ГБ видеопамяти (Nvidia GPU) или Mac с достаточной RAM
3. В форке добавлена загрузка в 4 бита для экономии памяти
4. В форке добавлена поддержка Mac (MPS)
5. Агент подключается к Minecraft через мод AltaClev (не через MinerL/Gym)
6. Docker-контейнер ~60 ГБ, запуск может занять 5-15 минут

### Запуск Rocket (старый визуальный агент)

1. Клонировать форк Rocket 2 из репозитория автора
2. Запускается из Docker
3. Более простой, чем Optimus, но показывает принцип работы визуальных агентов
4. Использует хардкоженную архитектуру с распознаванием объектов на экране

### MCP для Mineflayer (проект Ани)

Создание набора инструментов (tools) для Minecraft через Mineflayer с MCP-протоколом. Позволяет подключать LLM-агентов к Minecraft через стандартный MCP-интерфейс (совместимость с Claude и другими MCP-клиентами). В стадии доработки до полного соответствия MCP-протоколу. Потенциально — open-source библиотека.

### Go-оркестратор (проект Владимира)

Полный pipeline на Go: оркестратор связывает Python-сервисы (STT, TTS) и LLM. Конкурентность Go позволяет параллельно запускать разные части pipeline. STT и TTS — отдельные Python-скрипты, запускаемые как сервисы. На Mac используется QN3 TTS, адаптированная под MLX (Apple Silicon) — работает быстрее, чем в Docker. Bash-скрипт старта поднимает все сервисы последовательно.

**TTS QN3 для Mac:** специальная адаптация под MLX (нейронный процессор Apple Silicon). Недоступна в Docker. Работает значительно быстрее нативно. Генерация ответа: ~2-3 сек от LLM, остальное — TTS.

## Инструменты и технологии

- **VPT (Video PreTraining)** — модель OpenAI, обученная на видео Minecraft. Базовая архитектура для Action Head
- **Steve-1** — дообученная версия VPT, используется как Action Head в Optimus
- **Optimus 3** — VLA-агент для Minecraft (Qwen 2.5 VL + Action Head + Task Router). Есть V2 с улучшениями
- **MinerL** — Gym-среда для обучения Minecraft-агентов в Docker (сотни параллельных экземпляров)
- **OpenAI Gym** — стандарт сред для обучения агентов
- **LoRA (Low-Rank Adaptation)** — метод добавления адаптеров к LLM без полного переобучения
- **MLX** — фреймворк Apple для запуска ML-моделей на Apple Silicon (используется для TTS и LLM на Mac)
- **QN3 TTS** — TTS-модель, адаптированная под MLX для быстрой работы на Mac
- **Mineflayer** — JavaScript-библиотека для создания ботов Minecraft (headless, без графического клиента)
- **MCP (Model Context Protocol)** — протокол подключения инструментов к LLM-агентам (стандарт Anthropic)
- **Go** — язык программирования, использованный для написания оркестратора (конкурентность)
- **Rocket** — VLA-агент для Minecraft, более старый и простой, чем Optimus

## Ответы на вопросы студентов

**В: Видео для обучения VLA — специально записаны или из интернета?**
О: Разные этапы используют разные данные. Для VPT — огромный объём видео из интернета (YouTube). Для Action Head — специально записанные видео с привязкой к вводу клавиатуры/мыши (записывается и экран, и нажатия). Fine-tuning на конкретные задачи — размеченные данные с reward-функцией.

**В: Есть ли у Optimus способность к генерализации? Может ли он построить портал в модифицированном Minecraft?**
О: Нет. Задачи хардкодятся как классификатор. Агент не может понять произвольное текстовое описание действия. Нет задач, связанных со строительством (максимум — поставить один блок). Понимание 3D-строительства + произвольных инструкций — нерешённая задача для текущих архитектур.

**В: Насколько развита область open-world агентов?**
О: Слабо, несмотря на хайп. Лучшие результаты — хардкод (захардкоженные задачи). Нет универсальной модели, которая одновременно понимает мир, планирует и действует. Модели не могут быстро и нормально совмещать понимание и действие. До AGI-уровня в открытом мире — очень далеко.

**В: Почему LLM повторяет одни и те же шутки?**
О: Фундаментальная проблема LLM. Даже с repetition penalty — не решается полностью. При большом контексте сэмплирование склоняется к одним и тем же паттернам. При обнулении контекста — теряется память о предыдущих шутках. Нужны специальные механизмы отслеживания уже сказанного.
