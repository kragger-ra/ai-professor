# Симуляция апробации 2026-05-16 — критические находки

Симуляция на ведущем (Семён в роли S01) выявила **два блокера** для апробации с реальными добровольцами 18-20.05.

## BUG-1: Парсинг "первую тему" → RAG-запрос дословно

**Симптом:** Фраза «Привет, я Семён. Давай разберём первую тему» распарсилась как:
```
[TUTOR] Topic lecture request: 'первую тему'
```
RAG нашёл VLA (Vision Language Action из week 4) как первое совпадение для буквальной строки «первую тему». LectureManager запустил 11-блочный план «Сценарии и роли в архитектуре и проектах» — не то что просил пользователь.

**Корневая причина:** регекс выдёргивает дословный topic из voice-команды без понимания контекста («первую тему» ≠ конкретная тема курса).

**Воспроизведение:** `core_agent._handle_tutor_topic_lecture` принял "первую тему" как полноценный RAG-query.

**Фикс (до 18.05):** в `volunteer_pre_session_remote.md` обновить начальную фразу на конкретную:
> «Привет, я <имя>. Расскажи мне про память агента.»
Также: в `_handle_tutor_topic_lecture` либо отвергать слишком общие запросы («первую тему», «вторую тему», «третью тему»), либо при отсутствии конкретики попросить уточнить.

## BUG-2: Stop-команды во время лекции не работают (race condition)

**Симптом:** Студент несколько раз сказал «Стоп», «Помолчи», «Расскажи про память агента» — все три раза:
- TTS interrupt сработал (звук обрывался ~0.5 сек — фикс 15.05 работает)
- STT правильно транскрибировал фразы
- НО `_handle_lecture_interrupt` не вызывался → лекция продолжалась на следующий блок

**Корневая причина:** `core_agent.py:741` проверяет
```python
if len(self.ctx_handler.ctx_chat) > _chat_len_before:
    self._handle_lecture_interrupt()
else:
    _agent_log("[LECTURE] Silence after block, continuing")
```
Проверка идёт в момент паузы между блоками. STT-транскрипция (~3-4 сек после конца речи) приходит **позже**, чем проверка `_chat_len_before`. Pipeline считает паузу «тишиной» и переходит к следующему блоку.

В логах все 3 попытки stop-команды попали в ctx_chat, но не в нужное окно времени:
```
18:31:06 [MIC-STT] TTS interrupt after 4 blocks of speech
18:31:10 [MIC-STT] >>> Извините, стоп. Помолчите.
18:31:10 [LECTURE] Silence after block, continuing to 3/11   ← должно было поймать
18:31:40 [MIC-STT] >>> Извините, помолчи.
18:31:48 [MIC-STT] >>> Расскажи про что такое память агента.
```

**Фикс (до 18.05) — варианты:**
1. **Минимальный:** в `core_agent.py:740` добавить ожидание STT-flush (~5 сек) до проверки ctx_chat. Цена — каждая пауза между блоками удлиняется на 5 сек.
2. **Правильный:** убрать `_chat_len_before`-снэпшот, заменить на event-driven: подписаться на новое STT-событие во время паузы и реагировать, как только оно приходит, до начала следующего блока.
3. **Workaround:** добавить кнопку «Stop lecture» в Gradio UI для аварийной остановки.

**Критичность:** добровольцы в 30-минутной сессии застрянут в неправильной лекции — это убивает Этап 3 целиком.

## BUG-3: STT искажает короткие команды + фильтр "addressed to professor" режет искажённые формы

**Симптом (продолжение симуляции):** Студент 5 раз сказал «Закончи лекцию / Профессор закончи лекцию». В логах STT расшифровал как:
```
18:31:35 >>> 'Извините, стоп.'
18:31:40 >>> 'Извините, помолчи.'
18:31:48 >>> 'Расскажи про что такое память агента.'
18:33:47 >>> 'Последний блок, спасибо лектор.'
18:34:13 >>> 'Конец не более.'
```
Лишь две из них достигли `_handle_lecture_interrupt` (потому что окно проверки timing-чувствительно, см. BUG-2). Из этих двух обе отфильтрованы:

```
[LECTURE] Student said: 'Конец не более.'
[LECTURE] Not addressed to professor, ignoring: 'Конец не более.'
```

**Корневая причина:** `core_agent.py:822-831` — внутри лекции команда принимается только если:
- содержит «профессор / преподаватель / препод» (обращение), ИЛИ
- содержит «что такое / как работает / расскажи / объясни / не понял / повтори / зачем / почему», ИЛИ заканчивается на `?`

End-команды (`закончи лекцию` и т.д.) проверяются ДО этого фильтра (`_END_LECTURE_PHRASES` строка 789), но если STT исказил фразу — она не попадает в этот whitelist и отлетает на фильтре адресации.

Whisper-faster STT на коротких 1-3-сек фразах через системный микрофон выдаёт значительные искажения. Длинные фразы (5+ слов) транскрибируются точнее.

**Фикс (до 18.05) — варианты:**
1. Снизить строгость фильтра адресации: пропускать также фразы с любыми stop-keywords (`стоп / хватит / закончи / помолчи` в искажённых формах через fuzzy-match).
2. Добавить ASCII-кнопку «End lecture» в Gradio UI — текстовая страховка против STT-искажений.
3. Использовать VAD-чувствительный mic-prompt: «Если хочешь остановить, скажи длинно: <Профессор остановись пожалуйста>».
4. Снизить чувствительность Whisper к коротким аудиофрагментам (`SPEECH_MIN_BLOCKS` повысить или transcription_timeout удлинить).

**Критичность:** студент в апробации физически не сможет остановить тьютора голосом, если первая фраза исказилась. Без UI-кнопки — только перезапуск.

## BUG-4: TypeError в проверочном вопросе после блока (None в check_q)

**Симптом:**
```
[18:39:12] [LECTURE] ERROR in phase=delivering: expected string or bytes-like object
File "core_agent.py", line 729, in _lecture_step
    self._send_to_tts(check_q)
File "core_agent.py", line 531, in _send_to_tts
    text = self._EMOTION_PAREN_RE.sub('', text)
TypeError: expected string or bytes-like object
```

**Корневая причина:** `_lecture_step` генерирует проверочный вопрос (`check_q`) через LLM между блоками. В этот раз LLM вернул `None` (timeout / пустой stream / парсинг отказал). `_send_to_tts` ожидает строку, регекс `EMOTION_PAREN_RE.sub('', None)` падает с TypeError.

**Pipeline восстановился** — exception поймался в общем try/except `_lecture_step`, и следующий блок пошёл нормально. **Но проверочный вопрос пропадает** — потерянная функциональность «3-5 предложений + пауза + проверка» из фикса 15.05.

**Фикс (тривиальный):**
```python
# core_agent.py:529 (предположительно перед line 531)
def _send_to_tts(self, text):
    if not text:
        return  # silent no-op для None / empty
    text = self._EMOTION_PAREN_RE.sub('', text)
    ...
```
Или защита на источнике в `_lecture_step:729`:
```python
if check_q:
    self._send_to_tts(check_q)
```

**Критичность:** низкая (нет потери темы, нет краша всего pipeline), но если check_q регулярно None — пропадает важная педагогическая фича. Если только один раз за лекцию — терпимо.

## Хорошие новости — что РАБОТАЕТ

- **Перебивание TTS** (фикс 15.05) — звук рвётся ~0.5 сек, фикс на месте.
- **Stop-команды в `qa_audience` фазе** — работают (там фильтр мягче, чем в `delivering`).
- **Topic-lecture с конкретным названием** — «Расскажи про что такое память агента» распарсилось правильно как `Topic lecture request: 'память агента'`, RAG нашёл правильный материал. Проблема только с абстрактными запросами («первую тему»).
- **Pipeline-стек поднимается стабильно** — Vosk + Gradio + LM Studio + RAG за ~90 сек.
- **STT распознаёт длинные фразы точно** — 5+ слов идут без искажений.
