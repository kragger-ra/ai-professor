## Часть I. Концепция вайб-кодинга и инструменты

**1.** От чего, согласно материалу, зависит итоговое качество работы в вайб-кодинге?

а) От того, насколько хорошо человек сам владеет языком программирования
б) От настройки инструмента-исполнителя и полноты описания результата
в) От пропускной способности интернета и мощности компьютера пользователя
г) Исключительно от того, какая именно языковая модель используется

**2.** Чем работа с моделями в 2022–2023 годах отличалась от современной?

а) Тогда писать код было трудоёмко: множество правок и лишь мелкие фрагменты
б) Тогда модели справлялись быстрее, поскольку задачи в целом были проще
в) Тогда код вводился преимущественно голосом, сейчас — преимущественно текстом
г) Принципиальной разницы нет, изменилась только стоимость подписки

**3.** Как трактуется текущий результат моделей на SWE-Bench?

а) Как свидетельство, что модели пока непригодны для реальной разработки
б) Как подтверждение, что Claude Code обгоняет Codex по скорости работы
в) Как требование к производительности компьютера пользователя
г) Как показатель технологической зрелости методики работы с кодом

**4.** Какой статус сейчас у промпт-инжиниринга как отдельной дисциплины?

а) Стал важнее всего: без специальных приёмов модель не работает корректно
б) Актуален только для платных моделей, для бесплатных не требуется
в) В качестве самостоятельной дисциплины утратил релевантность
г) Применим только в задачах, связанных с изображениями

**5.** Кому из инструментов лучше поручить дизайн лендинга, а кому — доработку и тесты?

а) Дизайн — Codex, доработку и тесты — Claude Code
б) Дизайн — Claude Code, доработку и тесты — Codex
в) Оба инструмента одинаково сильны во всех направлениях
г) И дизайн, и тесты лучше всего делает только Claude Code

**6.** Чем оправдано то, что Codex работает дольше Claude Code на одной и той же задаче?

а) Лишние 10–15 минут компенсируются точностью соответствия результата ожиданиям
б) Медленный инструмент даёт результат хуже, оправдания этому нет
в) В действительности Codex быстрее Claude Code, утверждение ошибочно
г) Дольше работает только бесплатная редакция Codex, платная — нет

**7.** Как на практике выглядит кросс-модельная работа?

а) Обе модели запускают параллельно и берут тот результат, что готов раньше
б) Задачу разбивают на отдельные строки и распределяют между двумя моделями
в) Сначала консультируются с экспертом-человеком, а только затем с моделями
г) Основному инструменту поручают обратиться к Claude за планом

**8.** Чем результат с референсом отличается от результата без него?

а) С референсом результат стабильно получается хуже, чем без него
б) Различий нет, референс влияет только на скорость выполнения задачи
в) Без референса модель скатывается к шаблону, с референсом — оригинальнее
г) С референсом модель перестаёт задавать уточняющие вопросы пользователю

## Часть II. Рабочий процесс в Codex и Claude Code

**9.** Чем приходится платить за удобство режима YOLO?

а) Удвоенным расходом лимита запросов на каждое действие
б) Повышенным риском: действия исполняются без проверки человеком
в) Потерей доступа к интернету у исполнительного агента
г) Невозможностью использовать Plan Mode в той же сессии

**10.** Почему держать сведения о проекте в файле-контексте эффективнее, чем каждый раз заново анализировать проект?

а) Повторное обследование при каждом обращении тратит время и токены
б) Без файла-контекста модель не сможет открыть файлы проекта
в) Файл-контекст делает обращения к модели бесплатными
г) Без него инструмент не сможет подключаться к интернету

**11.** Почему на большом проекте модель может «забыть» правила работы с ним?

а) Потому что модель намеренно игнорирует инструкции, считая их устаревшими
б) Потому что в крупных проектах автоматически отключается доступ к интернету
в) Потому что работа с большим проектом требует отдельной платной подписки
г) Потому что контекст ограничен, и все детали большого проекта в него не помещаются

**12.** Почему с Plan Mode безопасно начинать произвольную работу?

а) В нём модель не расходует лимит запросов, что снимает все ограничения
б) В нём автоматически создаётся резервная копия всех файлов проекта
в) В нём у модели только право чтения, испортить файлы она не может
г) В нём задействуется только проверенная стабильная редакция модели

**13.** Чем уровень `xhigh` отличается от `low`?

а) `xhigh` быстрее `low`, потому что пропускает этап планирования
б) `xhigh` медленнее и дороже по лимиту, но эффективнее на сложных задачах
в) `xhigh` работает без интернета, а `low` — только с интернетом
г) Разница только в названии, фактическое поведение совпадает

**14.** Как выглядит приём кросс-модельной проверки качества?

а) Работу Codex проверяет в режиме ревизии Claude Code, и наоборот
б) Человек вручную сверяет код с эталоном построчно
в) Модель запускает код и фиксирует, выпала ли при исполнении ошибка
г) Проект отдают на проверку другому пользователю инструмента

**15.** Что произойдёт, если работать с проектом полностью без Git?

а) Проект станет работать заметно медленнее на любом устройстве
б) Модель перестанет создавать в проекте новые файлы без репозитория
в) Проект нельзя будет открыть и запустить на другом компьютере
г) Не будет истории изменений и возможности откатиться назад

**16.** Что происходит при слиянии (merge) веток?

а) Все ветки, кроме основной, безвозвратно удаляются после слияния
б) Проект автоматически публикуется в открытом доступе на сервере вендора
в) Git объединяет ветки и сам состыковывает файлы для совместной работы
г) История изменений всего проекта полностью очищается после операции
