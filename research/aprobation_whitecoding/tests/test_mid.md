## Часть I. Концепция вайб-кодинга и инструменты

**1.** На кого ложится написание кода в типичной сессии вайб-кодинга?

а) Человек пишет основную часть, ИИ дописывает повторяющиеся куски
б) Человек и ИИ пишут код пополам, чередуясь по строке
в) ИИ-инструмент порождает код по словесному описанию от человека
г) Человек пишет каркас на одном языке, ИИ переводит его в другой

**2.** Что характеризует сдвиг 2024 года в работе моделей с кодом?

а) Появились первые расширения для редакторов, способные предлагать код
б) Все ведущие инструменты стали бесплатными для индивидуальных пользователей
в) Языковые модели научились исполнять собственный код в песочнице
г) Мощные модели начали выдавать большие связные работоспособные куски кода

**3.** Как современные модели обычно выглядят на тестах SWE-Bench?

а) Стабильно решают свыше 80% задач, включая нетривиальные
б) Решают около пятой части задач — пока только самые простые
в) Решают ровно половину задач — половина остаётся непокрытой
г) Закрывают весь набор задач полностью, без пропусков

**4.** Какая причина чаще всего стоит за результатом «модель сделала не то»?

а) Модель выбрала не тот режим планирования и не переключилась обратно
б) В описании задачи не хватило деталей, модель работала по тому, что дали
в) Не сработала интеграция с диалоговым интерфейсом ChatGPT в этой сессии
г) Был выбран неподходящий тарифный план для задач такой сложности

**5.** Чем Codex отличается по характеру работы от Claude Code?

а) Стабильнее ведёт себя на больших проектах, но проигрывает в дизайне интерфейсов
б) Запускается быстрее, но не имеет встроенного режима ревизии кода
в) Работает только с текстовыми документами, программный код он не пишет
г) Действует консервативно: предпочитает аккуратную реализацию ускорению

**6.** Почему Codex обычно тратит на типовую задачу больше времени?

а) Он каждый раз заново подгружает языковую модель с сервера
б) В нём дольше идёт начальная авторизация в подписке ChatGPT
в) Он тщательнее работает со стилизацией, и его результат предсказуемее
г) Он всегда обязательно запрашивает подтверждение каждого действия

**7.** Зачем в работе комбинируют сразу два разных инструмента?

а) Один инструмент быстро исчерпывает лимиты, второй нужен на подмену
б) Ни один из инструментов не закрывает все задачи одинаково хорошо
в) Лицензия Anthropic требует обязательного использования в паре с Codex
г) Два инструмента вместе работают пропорционально быстрее одного

**8.** Что даёт модели предоставление референса-образца?

а) Модель опирается на заложенную в нём концепцию и расширяет её
б) Модель копирует образец один в один без изменений
в) Модель сокращает расход лимита запросов на этой задаче
г) Модель переходит в специальный визуальный режим работы

## Часть II. Рабочий процесс в Codex и Claude Code

**9.** Что произойдёт после команды `codex`, если флаг `--yolo` не указан?

а) Инструмент сразу зафиксирует начальное состояние проекта в Git
б) Инструмент проигнорирует команду и переключится в Plan Mode
в) Инструмент будет запрашивать подтверждение перед каждым действием
г) Инструмент откроет проект только в режиме чтения, без правок

**10.** Что хранится в проектном файле-контексте, который создаёт `init`?

а) Полная резервная копия всех файлов проекта на момент создания
б) Журнал всех действий пользователя, выполненных в инструменте
в) Список всех запросов, отправленных модели за текущую сессию
г) Описание проекта, его стек, частые команды и правила изменений

**11.** Что произойдёт с тем, что модель «помнит», при перезапуске инструмента?

а) Контекст обнулится — предшествующий диалог будет утрачен
б) Контекст сохранится в локальном файле и подтянется автоматически
в) Контекст уйдёт в облако вендора и будет восстановлен по запросу
г) Сохранится только последнее сообщение пользователя

**12.** В чём суть режима планирования (Plan Mode)?

а) Составить план и сразу, не показывая его, приступить к выполнению
б) Сначала обсудить замысел и зафиксировать план, и только потом — реализация
в) Выполнить задачу обычным образом, отчёт с планом приложить в конце
г) Ускорить работу за счёт пропуска уточняющих вопросов модели

**13.** На каком уровне команды `model` обычно решают элементарную задачу?

а) Только xhigh, иначе модель ошибётся даже на простом
б) Уровень для простых задач не важен, можно ставить high по умолчанию
в) Для простых задач команду `model` использовать не рекомендуется
г) Достаточно low или medium — они и быстрее, и дешевле по лимиту

**14.** Почему изменения полезнее проверять не той же моделью, что их вносила?

а) Одна модель технически не может одновременно писать код и запускать `review`
б) При смене модели вдвое снижается расход лимита запросов на ревью
в) Модель плохо замечает свои ошибки, сторонняя видит их свежим взглядом
г) Лицензия запрещает одному инструменту проверять собственный вывод

**15.** Зачем нужна история коммитов в Git?

а) Чтобы модель могла обучаться на истории изменений этого проекта
б) Чтобы видеть состав и время изменений, а при сбое откатиться назад
в) Чтобы автоматически синхронизировать проект с серверами вендора модели
г) Чтобы инструмент мог сам исправлять ошибки в коде по истории

**16.** Для чего обычно используют ветки в Git?

а) Чтобы участники работали параллельно, каждый в своей ветке независимо
б) Чтобы ускорить итоговую сборку проекта за счёт распараллеливания
в) Чтобы хранить разные языковые версии интерфейса в отдельных ветках
г) Чтобы каждый отдельный коммит записывался в собственный файл
