# Апробация ИИ-тьютора — курс «Программирование на естественном языке» (вайб-кодинг)

Пакет материалов для апробации с добровольцами. Новый предмет, новый корпус.
Подготовлено 2026-05-21.

## Состав пакета

```
research/aprobation_whitecoding/
├── README.md              ← этот файл: порядок проведения
├── free_study_text.md     ← трудносформированный текст для самостоятельного изучения
├── survey.md              ← анкета обратной связи
└── tests/
    ├── test_pre.md        ← тест 1, входной (перед всем)
    ├── test_mid.md        ← тест 2, после чтения текста
    ├── test_post.md       ← тест 3, после тьютора
    └── KEY.md             ← ключи + source coverage + методика (НЕ выдавать добровольцам)
```

Корпус курса (то, на чём работает RAG тьютора):
`courses/whitecoding/00_whitecoding_canonical.md` + `course_config.yml`.
Это тот же текст, что `free_study_text.md`, — студент его читает, тьютор
по нему отвечает.

Отчёт о валидации RAG: `research/eval_whitecoding/RAG_VALIDATION.md`.

## Порядок проведения сессии

Дизайн — три замера знаний вокруг двух воздействий (тяжёлый текст и тьютор):

| Шаг | Что делает доброволец | Материал | ~Время |
|---|---|---|---|
| 1 | Проходит **входной тест** | `tests/test_pre.md` | 10 мин |
| 2 | **Самостоятельно читает** тяжёлый текст | `free_study_text.md` | 15–20 мин |
| 3 | Проходит **промежуточный тест** | `tests/test_mid.md` | 10 мин |
| 4 | **Голосовая сессия с ИИ-тьютором** по обеим темам | тьютор | 25–30 мин |
| 5 | Проходит **итоговый тест** | `tests/test_post.md` | 10 мин |
| 6 | Заполняет **анкету** | `survey.md` | 5–7 мин |

Итого ~75–85 минут на доброволца. Между сессиями разных добровольцев —
перерыв не менее 30 минут.

Тесты можно перенести в Google Forms (как в прошлой апробации) или давать как
есть — формат `.md` читается напрямую. Тексты тестов не показывать добровольцу
заранее; `KEY.md` не выдавать никогда.

## Что должно быть готово до первой сессии

1. **LM Studio запущен**, порт 22227, загружена модель эмбеддингов
   `text-embedding-user-bge-m3` (нужна для RAG).
   Проверка: `lms ps` показывает модель.
2. **RAG-индекс собран** — `data/rag_vector_store/` (44 чанка). Уже собран;
   при необходимости пересобрать:
   `.venv\Scripts\python.exe research\eval_whitecoding\_wc_01_build_index.py`.
3. **Активный курс** — `data/current_course.json` указывает на «Вайб-кодинг»
   (уже выставлено). Альтернатива — голосом в начале сессии: «загрузи курс
   вайб-кодинг».
4. **LLM тьютора** — действующий ключ OpenAI в `.env` (`gpt-5.4`).
5. **Smoke-проверка тьютора** до первой сессии: задать 2–3 вопроса из обеих тем
   («Что такое Plan Mode?», «Чем Claude Code отличается от Codex?», «Что такое
   коммит?»). Если тьютор отвечает «нет в материалах» или выдумывает — RAG не
   подхватился, разобраться до старта.

## Скоринг и гипотеза

Балл за тест = число правильных из 16 (ключи в `tests/KEY.md`). По каждому
доброволцу:

- **Δ_текст** = тест 2 − тест 1 — вклад самостоятельного чтения тяжёлого текста;
- **Δ_тьютор** = тест 3 − тест 2 — вклад работы с тьютором;
- **Δ_итог** = тест 3 − тест 1 — суммарный прирост.

Порог «обучение состоялось»: Δ_итог ≥ +3 из 16 при тесте 3 ≥ 9; среднее Δ_итог
по группе ≥ +1.5. Раздельный учёт Δ_текст и Δ_тьютор позволяет на защите
показать, какой вклад дал именно тьютор поверх чтения.

## Темы курса (что проверяется)

**Тема 1 — концепция и инструменты:** сущность вайб-кодинга, эволюция моделей,
SWE-Bench, принцип полного ТЗ, Claude Code vs Codex, скорость, кросс-модельный
процесс, роль референса.

**Тема 2 — рабочий процесс:** режимы санкционирования и YOLO, команда `init` и
файл-контекст, ограничение контекста, Plan Mode, команда `model`, код-ревью и
кросс-верификация, Git (коммит/история/откат), Git (ветки/слияние).

По каждой теме — 8 вопросов в каждом из трёх тестов (одни концепты, разные
формулировки и порядок вариантов).
