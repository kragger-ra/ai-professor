### **Конспект лекции: Создание ИИ-персонажей (PersonaLab Workshop) – RAG-системы**

---

#### **1. Ключевые концепции и определения**
- **RAG (Retrieval-Augmented Generation)** – метод, объединяющий поиск релевантной информации из базы знаний (retrieval) и генерацию текста языковой моделью (generation).
  - *Задача*: Компенсировать ограниченность общих знаний LLM (языковой модели) за счёт подключения внешних данных.
  - *Применение*: Создание ИИ-персонажей с уникальными знаниями (например, для конкретного проекта).
- **Эмбеддинги (embeddings)** – числовые векторы, представляющие семантическое содержание текста.
  - *Размерность вектора*: 1024 (в данном случае).
- **Чанки (chunks)** – фрагменты текста, на которые разбивается база знаний для индексации.
- **Векторный поиск** – метод поиска релевантных чанков по близости векторов (например, через косинусное сходство).

---

#### **2. Практические инструкции и команды**
- **Технический процесс RAG**:
  1. **Разбиение текста** на чанки.
  2. **Преобразование чанков** в векторы (эмбеддинги) с помощью модели (например, Mistral Embed).
  3. **Индексация векторов** в базе данных (FAISS/ChromaDB).
  4. **Поиск ближайших векторов** при запросе пользователя (через FAISS).
  5. **Подстановка найденных чанков** в контекст LLM для генерации ответа.
- **Инициализация RAG-модели**:
  ```python
  # Пример (предположительно):
  rag_model = RagModel()
  rag_model.initialize_faiss()  # Инициализация FAISS
  rag_model.load_documents()    # Загрузка документов
  ```

---

#### **3. Упомянутые инструменты и технологии**
- **Модели для эмбеддингов**:
  - **Mistral Embed** – модель для генерации векторных представлений текста.
- **Векторные базы данных**:
  - **FAISS** (Facebook AI Similarity Search) – быстрая библиотека для поиска по векторам (оптимизирована для производительности).
  - **ChromaDB** – альтернатива FAISS, удобнее для прототипирования, но медленнее.
- **Класс `RagModel`** – абстракция для работы с RAG (инициализация FAISS, загрузка документов).
