## 1. Архитектура пайплайна ИИ-стримера и оркестрация
- **Pipeline (конвейер):** Последовательность `STT → LLM → TTS`, обеспечивающая голосовое взаимодействие персонажа.
- **Оркестратор:** Центральный компонент на Go, связывающий независимые Python-сервисы (STT/TTS) и управляющий потоком данных.
- **Стриминг TTS:** Разбиение ответа LLM на предложения для параллельной генерации и озвучки. Позволяет начать воспроизведение первой части, пока генерируется вторая.
- **Проблемы стриминга TTS:** Фрагментарная генерация нарушает общую интонационную дугу и консистентность голоса между предложениями.
- **Задержки:** ~2–3 сек на LLM + до 5+ сек на TTS. Требует оптимизации перед финальной сдачей.
- **Социальная часть диалогового ИИ:** Отмечена слабость текущего блока: склонность к агрессии, низкая вариативность ответов, цикличное повторение фраз из-за зануления/переполнения контекста или особенностей сэмплирования.

## 2. VLA/VLM модели и Open World агенты (Minecraft)
- **VLA (Vision-Language-Action):** Архитектура, объединяющая компьютерное зрение, языковое понимание и генерацию физических действий (клики, нажатия клавиш) без промежуточных навигаторов.
- **VLM (Vision-Language Models):** Модели для анализа видеоряда, отслеживания смещения камеры и распознавания объектов в реальном времени.
- **VPT (Video Pre-Training):** Базовая модель OpenAI, обученная на миллионах видео прохождения Minecraft. Движения на видео сопоставлены с нажатиями клавиш.
- **Steve1:** Оптимизированная, более лёгкая версия VPT.
- **Action Head (Экшен-модель):** Компактный модуль-адаптер (~2 ГБ, до 1B параметров), преобразующий текстовый вывод LLM в управляющие сигналы. В архитектуре Optimus слабее, чем в базовой VPT, так как ресурсы перераспределены в пользу планировщика.
- **Task Router / Plan-agent:** Модуль верхнего уровня, классифицирующий и декомпозирующий задачи. Маршрутизирует запросы между LLM (планирование) и Action Head (выполнение).
- **Двухуровневая архитектура:** `LLM-планер` (высокоуровневое рассуждение) + `Action-модель` (низкоуровневое исполнение). Коммуникация через токенизацию задач.
- **RL / Дообучение с подкреплением:** Тонкая настройка VPT под узкие задачи через систему наград (`+1`, «тепло/холодно»). Позволяет запоминать конкретные действия без общего понимания среды.
- **Генерализация:** Критическая проблема. Смена UI, добавление элементов (voice-chat, эффекты зелий), переход из Docker-среды в реальный мультиплеер резко снижают эффективность. Модели не способны к абстрактному обобщению (каждая новая задача требует отдельного дообучения или хардкода).
- **Random state machine:** Аналогия поведения необученной сети (случайные контроллы). Обученный агент — эволюционировавшая версия с детерминированным, но стохастическим поведением.
- **Тикрейт и FPS восприятия:** Агент обрабатывает визуальный поток с частотой ~8–9 FPS. Синхронизация тикрейта сервера на `7–8` упрощает навигацию. Время инференса модели меньше времени захвата скриншота (`getScreenshot`), что указывает на узкое место в пайплайне.
- **Хардкод в пайплайнах:** Валидация выполнения задач (например, наличие предмета в инвентаре) часто идёт через прямой запрос к коду игры, а не через нейросетевое рассуждение.
- **Поведение в ограниченной среде:** Агенты стремятся выйти из замкнутых пространств (например, «стеклянной колбы»), обычно не оставаясь в них дольше часа.
- **Статус AGI:** Отсутствие универсальной архитектуры, одновременно понимающей 3D-пространство, планирующей и действующей, указывает на то, что до AGI ещё далеко.

## 3. Computer Use агенты и генерация игровых сред
- **Computer Use агенты:** ИИ для автономного взаимодействия с графическими интерфейсами (клики, ввод текста, отслеживание экрана). Развиваются стабильнее и перспективнее узкоспециализированных Minecraft-агентов.
- **UI-TARS / Y-TARS (ByteDance):** VLA-модели для управления интерфейсами. Версия `7B` открыта, новые версии частично закрыты. Для локального запуска требуются конкретные релизы (`0.22`/`0.23`), так как последние несовместимы с локальной моделью `UITars 1.5 7b`.
- **Генерация интерактивных 3D-миров:** Создание пространств по входным фотографиям или текстовым запросам.
- **Oasis (Google):** Платформа/модель для генерации игровых сред на лету.
- **Hunyuan World:** Модель для генерации 3D-миров по фотографиям.
- **Atari Diamond / Diamond:** Проект генерации классических игр и шутеров (в т.ч. CS:GO) через нейросети.
- **World-модели / Diffusion Transformer:** Архитектура, предсказывающая следующее состояние мира на основе действий пользователя.
- **Dreamer V3:** Архитектура агента с обучением на внутреннем самостимуле (intrinsic motivation), формирующем награды на основе энтропии выходов и интереса к исследованию.

## 4. Протоколы, интеграции и навигация
- **MCP (Model Context Protocol):** Протокол стандартизации инструментов. Позволяет создавать кросс-платформенные библиотеки тулов, совместимые с любыми MCP-клиентами без привязки к конкретному скрипту.
- **Mineflayer:** Node.js библиотека для управления ботами в Minecraft.
- **Baritone / Автоклик:** Не являются нейросетями. Работают на эвристиках и алгоритме поиска пути `A*`. Эффективны для навигации и крафта, но не обладают способностью к абстрактному рассуждению.
- **LiteLLM:** Прокси-маршрутизатор для LLM API. **Проблема:** утечка метаданных региона в заголовках запросов приводит к автоматической блокировке API-ключей платформами.
- **LM Studio / LM Link:** Локальный запуск и управление LLM. Бета-версия `LM Link` позволяет синхронизировать модели и управлять инференсом между устройствами.
- **Captioning & Grounding:** Внутренние функции агента для текстового описания видимого и привязки объектов к экранным координатам.

## 5. Практические инструкции, запуск и отладка
- **Запуск пайплайна стримера:**
  1. Bash-скрипт стартует Python-сервисы (`python stt_server`, `python tts_server`) и ждёт их готовности.
  2. Запуск оркестратора на Go.
  3. Проверка голосового чата в Minecraft: клавиша `V`.
- **Требования к ОС и железу:**
  - **Linux + NVIDIA GPU:** ~20 ГБ VRAM для Optimus 3, ~24 ГБ для генеративных моделей.
  - **macOS:** Apple MLX / MPS для ускорения. Docker ограничен в доступе к Neural Engine/GPU.
  - **Windows/macOS «голые»:** Конфликты с Java и зависимостями. Требуется Docker или форки с патчами.
- **Docker:** Образы ~50–60 ГБ, инициализация 5–15 минут. Возможны падения, требуется ручное открытие портов.
- **Сеть и прокси:** Требуется VPN для загрузки зависимостей и подключения к серверам. Настройка `HTTP proxy` и `export` переменных. Возможны конфликты с антивирусами (ESET), блокирующими загрузку библиотек.
- **Патчи лектора:** Загрузка моделей в **4 бита** (экономия памяти), поддержка **MPS**, форк Optimus 3 для прямой интеграции с интерфейсом Minecraft (вместо изолированной MineStudio).
- **Отладка:** Ошибки `MacOS socket server broken pipe`, `EOF`. Перезапуск пайплайна сбрасывает состояние и зацикленные действия. Веб-интерфейс: `http://<IP>:8888`. Смена браузера (на Яндекс) может решить проблемы отображения.
- **Эксперимент с тюрьмой:** Построить клетку из железных прутьев, поместить агента и проверить способность удерживать клик для разрушения и побега.
- **Управление в демо:** Ввод задач (`get food`, `kill player` — последний не распознаётся, т.к. отсутствует в датасете). Инвентарь и экипировка выдаются вручную, агент не гарантирует их использование.
