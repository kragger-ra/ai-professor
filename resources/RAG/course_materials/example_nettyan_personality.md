# Пример ИИ-личности: NetTyan — автономный стример

> Этот документ описывает NetTyan — реальный проект ИИ-персонажа со стримерскими функциями.
> Используется как пример архитектуры цифровой личности в рамках курса PersonaLab.
> AI Professor построен на базе этого проекта.

---

## Общее описание

NetTyan — автономный ИИ-стример для Minecraft. Персонаж ведёт прямые трансляции, общается голосом со зрителями, играет в Minecraft и принимает решения самостоятельно. Проект демонстрирует полный цикл создания цифрового персонажа: от промпт-инженерии до голосового пайплайна.

**Ключевые компоненты:**
- LLM (языковая модель) — мозг персонажа
- STT (распознавание речи) — слышит зрителей
- TTS (синтез речи) — говорит голосом персонажа
- Анимированный аватар (Live2D) — визуальное представление
- Инструменты (tools) — действия в игре и чате
- RAG — база знаний персонажа
- Профили пользователей — память о зрителях

## Архитектура агентов

NetTyan использует мультиагентную архитектуру с несколькими типами агентов:

### Типы агентов

| Агент | Назначение | Формат инструментов |
|-------|-----------|---------------------|
| ChatAgent | Основной агент, нативный вызов функций (bind_tools) | JSON function calling |
| CoreAgent | Устаревший агент, текстовый парсинг команд | Текстовые команды (!cmd, /cmd, @cmd) |
| ReactionAgent | Простой чат без инструментов | Только текст |
| PlannerAgent | Стратегическое планирование | Анализ текста |

### Оркестрация

Мультиагентная система запускает несколько итераций основного агента, затем вызывает планировщика:
```
MultiAgent.run():
  for i in range(3):         # 3 итерации чата
    chat_agent.step()         # основной агент с инструментами
  planner_agent.step()        # стратегическое планирование
```

### Вывод: что это даёт для дизайна персонажей

Мультиагентная архитектура позволяет разделить ответственность: один агент отвечает за разговор, другой — за стратегию. Это масштабируемый подход для сложных персонажей, которым нужно одновременно вести диалог и принимать решения.

---

## Двухканальный вывод: голос и чат

Ключевое архитектурное решение NetTyan — разделение голосового и текстового вывода:

| Канал | Что | Длина |
|-------|-----|-------|
| Голос (TTS) | Текстовый вывод LLM, озвучивается | Любая, LLM решает сам |
| Игровой чат | Minecraft чат, читают игроки | Коротко, <80 символов |

LLM самостоятельно решает, что сказать голосом и что написать в чат:
- Простая реакция → короткий голос + короткий чат
- Интересный вопрос → длинный голосовой ответ + краткое резюме в чат
- Игровое действие → тактический голос + вызовы инструментов
- Наблюдение → молчание

### Вывод для дизайна персонажей

Разделение каналов вывода решает проблему "скучных коротких ответов" — голос может быть развёрнутым и эмоциональным, а текст остаётся компактным. Этот принцип применим к любому персонажу с несколькими каналами коммуникации.

## Голосовой пайплайн (Speech Pipeline)

### Архитектура STT (распознавание речи)

```
[Микрофон] (16kHz mono)
  → [VAD] (детекция голоса по амплитуде)
  → тишина > 1с → отправка в STT
  → [Parakeet STT] (NVIDIA, ONNX, CPU)
  → распознанный текст → событие → агент
```

- STT бэкенд: Parakeet TDT 0.6B (ONNX, INT8 квантизация, CPU)
- Скорость: 18-30x быстрее реального времени
- Поддержка пунктуации и капитализации
- 25 языков включая русский

### Проблема переключения языков

Ни Parakeet, ни Whisper не справляются с переключением языков в рамках одного высказывания (например, русская фраза с английскими игровыми командами). Практическое решение: STT выводит на русском, LLM интерпретирует контекст.

### Вывод для дизайна персонажей

Голосовой пайплайн критически важен для создания "живого" персонажа. Задержка между речью пользователя и ответом персонажа определяет ощущение естественности разговора. Чем ниже латентность, тем более живым кажется персонаж.

## Конструирование промптов

NetTyan использует два подхода к построению промптов:

### Устаревший подход (prompt_constructor)

```
construct_prompt_messages():
  → format_events_with_roles()     # форматирование событий
    → preprocess_events()           # объединение и фильтрация
    → categorize_events()           # разделение по времени
    → format_single_event()         # "MINECRAFT CHAT [2m ago] User: msg"
  → construct_prompt()              # системный промпт + инструменты + статус игры
  → добавить события как повороты диалога
```

**Проблемы:** каждое событие — отдельное сообщение, сломанная альтернация ролей.

### Современный подход (message_builder)

```
build_chat_messages():
  → build_events_block()            # все события в один текстовый блок
  → system: характер + подсказки по инструментам
  → user: ситуация + ВСЕ события + напоминание
  → assistant: предыдущий ответ (опционально)
```

**Улучшения:** все события в одном сообщении, строгая альтернация, нативные инструменты через API.

### Оптимизация через кеширование промптов

Структура промпта оптимизирована под KV-кеш LLM:
- Стабильная часть (характер, инструменты, история) → в начале, кешируется
- Динамическая часть (текущая ситуация, новые события) → в конце, пересчитывается

Результат: TTFT падает с ~3.8с до ~0.4с при кешированном префиксе (15x ускорение).

### Вывод для дизайна персонажей

Структура промпта напрямую влияет на качество и скорость ответов персонажа. Правило: всё стабильное — в начало (кешируется), всё динамическое — в конец.

## Инструменты персонажа

NetTyan имеет набор инструментов для взаимодействия с миром:

- **speak** — произнести текст с эмоцией (neutral, happy, sad, angry...)
- **chat_simple** — написать в игровой чат (<80 символов)
- **save_user_info** — запомнить факт о пользователе в базу данных
- **agent_action** — выполнить игровое действие (через Baritone)
- **wait** — подождать перед следующим действием

### Формат инструментов

Современный ChatAgent использует нативный JSON function calling:
```json
{
  "name": "speak",
  "arguments": {"text": "Привет!", "emotion": "happy"}
}
```

Устаревший CoreAgent парсит текстовые команды:
```
>Привет! *happy*
!save_user_info User1 любит строить
```

### Вывод для дизайна персонажей

Инструменты определяют, что персонаж может делать в мире. Нативный function calling надёжнее текстового парсинга. Набор инструментов должен соответствовать роли персонажа.

---

## Память о пользователях

NetTyan сохраняет информацию о зрителях через инструмент `save_user_info`:
- Факты о пользователях записываются в базу данных
- При следующей встрече информация загружается в промпт
- LLM самостоятельно решает, что запомнить

### Вывод для дизайна персонажей

Память — ключевой фактор "живости" персонажа. Когда персонаж помнит предыдущие взаимодействия, пользователь воспринимает его как настоящую личность, а не как бота.

## Сравнение NetTyan и AI Professor

| Аспект | NetTyan (стример) | AI Professor (преподаватель) |
|--------|-------------------|------------------------------|
| Контекст | Minecraft стрим | Университетский курс |
| Цель | Развлечение зрителей | Обучение студентов |
| Голос | Fish Speech / Vosk TTS | Vosk TTS |
| STT | Parakeet (CPU, ONNX) | Whisper large-v3 (CUDA) |
| LLM | ChatAgent + MultiAgent | Streaming Orchestrator |
| Инструменты | Игровые (Minecraft) | Образовательные (RAG, конспекты) |
| Память | save_user_info (факты) | Профили студентов (SQLite + мета-агент) |
| RAG | Сленг-словарь | Лекции и материалы курса |
| Прерывание | Нет | 3 уровня (TTS, LLM, стоп-команды) |
| Интеграция | Twitch/Discord/YouTube | Zoom (VoiceMeeter) |

### Что было унаследовано от NetTyan

- Базовая архитектура агента (CoreAgent)
- Голосовой пайплайн (STT → LLM → TTS)
- Система событий и контекста (ctx_handler)
- Формат промптов (адаптирован под образовательный контекст)

### Что было добавлено в AI Professor

- RAG по материалам конкретного курса
- Адаптивные профили студентов через мета-агент
- Конспектирование лекций в реальном времени
- Трёхуровневая система прерываний
- Интеграция в видеоконференцию Zoom
- Потоковая генерация с предзагрузкой TTS (prefetch)
