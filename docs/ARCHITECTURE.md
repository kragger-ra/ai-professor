# Архитектура AI Professor — Tutor v2

Актуальное описание архитектуры сборки **Tutor** (ветка `tutor-v2`, пакет
`tutor/`). Документ ведётся как живая справка; раздел 7 фиксирует расхождения
с первой версией, раздел 8 — известные проблемы.

- **Дата актуализации:** 2026-05-22
- **Источники:** код `tutor/` (`app.py`, `brain/`, `audio/`, `tts/`), `CLAUDE.md`.
- **Связанные документы:** `README.md`, `tutor/README.md` (план фаз),
  `docs/VOICE_COMMANDS.md`, `../_vkr_tech_state.md` (раздел 6 — влияние пересборки
  на текст ВКР).

---

## 1. Обзор

Голосовой ИИ-тьютор для индивидуальной работы со студентом. Линейный конвейер
реального времени: **микрофон → STT → агент (RAG + LLM) → Vosk-TTS → динамик**,
с возможностью прервать речь голосом. Загружает свой курс из `.md`/`.txt`,
отвечает на вопросы, читает мини-лекции по запросу, ведёт кросс-сессионную
память.

Ключевой принцип v2 — **минимальная архитектура под линейную задачу**: один
процесс, потоки вместо процессов, обычные очереди вместо IPC. Это прямая
противоположность v1, унаследовавшей мультипроцессный «экзоскелет» у
стримингового мультиисточникового агента NetTyan (см. раздел 7).

## 2. Процессная модель и потоки

**Один процесс ОС.** Три долгоживущих рабочих потока (`threading.Thread`,
daemon), запускаются из `tutor/app.py`:

| Поток | Модуль | Роль |
|---|---|---|
| `capture` | `audio/capture.py` + `audio/stt.py` | микрофон, энергетический RMS-VAD, faster-whisper STT |
| `agent` | `brain/agent.py` | маршрутизация реплики, RAG, мета-агент, LLM, стек ответов |
| `playback` | `audio/playback.py` | озвучка объекта «Ответ» через Vosk-TTS, resumable |

Главный поток после старта только ждёт (`while capture.is_alive(): sleep(0.2)`)
и на выходе корректно гасит потоки.

**Транзиентные вспомогательные потоки** (создаются по ходу работы):
- `generate` — по одному на каждый ответ: тянет стрим LLM в объект «Ответ»;
- `memory-refresh` — раз в 6 ходов студента обновляет кросс-сессионную память;
- `ThreadPoolExecutor("preflight", max_workers=2)` — параллельный запуск
  мета-агента и RAG-поиска перед генерацией ответа;
- потоки `AmbientPlayer` — тихий эмбиент (по умолчанию выключен).

**Связи между потоками** — только in-process примитивы:
- `input_q: queue.Queue` — реплики студента (`str`) от capture к агенту;
- `tts_q: queue.Queue` — объекты «Ответ» от агента к playback;
- `interrupt: threading.Event` — выставляется capture на старте речи,
  сбрасывается агентом; playback по нему мгновенно глушит озвучку;
- `playback.speaking: threading.Event` — флаг «TTS играет», поднимает порог
  VAD в capture (анти-эхо);
- `capture.ready: threading.Event` — микрофон открыт, можно дать звуковой
  сигнал готовности.

Ни `multiprocessing`, ни `Manager`, ни IPC, ни прокси-объектов.

```
        +-------------------- interrupt (Event) --------------------+
        v                                                          |
   capture/STT  --input_q (Queue)-->  agent  --tts_q (Queue)-->  playback
                                        |                          |
                                  preflight pool             speaking (Event)
                                  (meta + RAG)                      |
                                        |                           v
                            generate-поток -> объект «Ответ»     Vosk-TTS :22232
```

## 3. Поток данных — один цикл Q&A

1. **capture**: RMS-VAD ловит речь, на старте выставляет `interrupt`. После
   паузы тишины буфер уходит в faster-whisper. Транскрипт чистится (фильтр
   галлюцинаций, словарь коррекций, fuzzy-коррекция по RAG-словарю), отсев
   фоновых реплик (`_BACKCHANNEL_PATTERNS`). Готовая строка + флаг
   `was_interruption` кладётся в `input_q`.
2. **agent** `_handle()` маршрутизирует реплику: pending-offer → стоп-команда →
   отказ-продолжать → continue/return → acknowledgement (в т.ч.
   comprehension-stop) → запрос мини-лекции → голосовая команда → обычный
   вопрос (см. раздел 5).
3. Для обычного вопроса: параллельно (preflight pool) запускаются мета-агент и
   RAG-поиск. Собирается системный промпт (`brain/prompt.py`), создаётся объект
   `Answer`, кладётся в стек.
4. Отдельный `generate`-поток тянет стрим LLM по предложениям
   (`stream_response_sentences`) и наполняет `Answer`. Объект `Answer` сразу
   кладётся в `tts_q` — озвучка идёт параллельно с генерацией.
5. **playback** читает `Answer`, синтезирует предложения через Vosk-TTS с
   упреждающим синтезом (prefetch), двигает `voiced_index`. По `interrupt` —
   мгновенная остановка.

## 4. Компоненты

### 4.1. Захват и распознавание — `audio/`
- `capture.py` — энергетический VAD на блоках 100 мс. Пороги:
  `SILENCE_THRESHOLD=300`, при играющем TTS — `SILENCE_THRESHOLD_WHILE_TTS=700`
  (анти-эхо). 4 блока речи на вход в запись, 10 блоков тишины на выход.
- `stt.py` — faster-whisper (`large-v3-turbo-russian`, дообученный под русский),
  `device=cuda`, `compute_type=float16`. Гейт уверенности по language_probability,
  чёрный список галлюцинаций, словарные коррекции терминов.

### 4.2. Агент — `brain/agent.py`
`AgentThread` — цикл обработки реплик. Хранит историю диалога (обычный список,
в промпт идут последние 6 ходов), personality, текущую манеру, стек ответов,
кросс-сессионную память, профиль. Маршрутизация — раздел 5.

### 4.3. Объект «Ответ» и стек — `brain/answer.py`
- `Answer` — вопрос + список предложений + `voiced_index` + флаг генерации.
  Генерация и озвучка **расцеплены**: текст копится в объекте, озвучка читает
  его отдельно. Возврат после прерывания доигрывает сохранённый текст из памяти
  без повторного вызова LLM.
- `AnswerStack` — стек ответов для вложенных уточнений (глубина 3, 4-й уровень
  отбивается фразой + парковка). **Вложенность временно отключена** флагом
  `_NESTING_AND_RETURNS_DISABLED` — см. раздел 8.

### 4.4. Мета-агент — `brain/meta.py`
Один вызов лёгкой модели (gpt-5.4-nano/mini, настраивается) перед генерацией,
параллельно RAG. Возвращает 7 полей: `mood`, `level` (1–5), `needs_analogy`,
`stt_garbled`, `ref` (разрешение анафоры), `stuck_on`, `style_hint`. Таймаут
ожидания — 4 с, при срыве — безопасные дефолты. Адаптация длины/словаря ответа
в мете НЕ делается — это работа основной LLM.

### 4.5. RAG — `brain/rag.py`, `brain/embeddings.py`
FAISS `IndexFlatL2`, эмбеддинги bge-m3 через LM Studio (:22227). Трёхуровневая
градация уверенности по L2-дистанции. `reload_from_path` — горячая пересборка
корпуса из папки `.md` (голосовая команда «загрузи курс …»). RAG пропускается
для коротких служебных реплик.

### 4.6. LLM — `brain/llm.py`, `brain/lm_client.py`
OpenAI-совместимый API через `litellm`. Основной режим — облачный OpenAI
gpt-5.4; локальный fallback — LM Studio (`USE_LOCAL_LLM`, переключается в `.env`
+ рестарт). `llm.py` — стриминг-оркестратор: токены → предложения (`SentenceBuffer`)
→ очередь TTS. Защита от зависания провайдера — wall-clock таймаут.

### 4.7. Синтез речи — `audio/playback.py`, `tts/vosk_client.py`
Vosk-TTS сервер (:22232), `speaker_id=4`. Полосный де-эссер (4 кГц), StressRNN
авто-ударения, паузы по пунктуации, упреждающий синтез, кэш фраз.

### 4.8. Память и профиль — `brain/session_memory.py`, `brain/profile.py`
- `SessionMemory` — тезисный rolling summary прошлых сессий
  (`data/session_memory.json`), грузится при старте, обновляется раз в 6 ходов
  и на выходе. Инжектится в системный промпт.
- `StudentProfile` — одиночный профиль (имя/бэкграунд) в JSON
  (`data/student_profile.json`). **Извлечение и инжект отключены** флагом
  `_PROFILE_DISABLED` — см. раздел 8.
- Сброс обоих файлов — `reset_memory.bat`.

## 5. Ключевые механизмы

**Маршрутизация реплики** (`agent._handle`, порядок проверок):
1. pending-offer (ожидается «да/нет» на проактивное предложение);
2. **стоп-команда** (`_STOP_RE`: стоп/стой/хватит/остановись/прекрати/…) —
   агент молчит, озвучка уже остановлена `interrupt`;
3. **отказ-продолжать** (`_REFUSE_RE`: «не продолжай», «дальше не надо» —
   повелительное наклонение) — завершает объяснение, чистит стек;
4. **continue** («продолжай») — доозвучка текущего ответа из памяти, без LLM;
5. **return** («вернёмся») — подъём к родителю по стеку (при отключённой
   вложенности вырождается в continue);
6. **acknowledgement** — реплика целиком из填filler-слов:
   - **comprehension-stop** (слово понимания/закрытия — понял/ясно/достаточно/
     всё — и НЕТ слова продолжения) → завершает объяснение, чистит стек;
   - иначе → continue (студент подтверждает, тьютор продолжает);
7. запрос мини-лекции → подтверждение → длинный ответ;
8. голосовая команда (`brain/commands.py`: манера, загрузка курса, пауза);
9. **обычный вопрос** → генерация ответа.

**Перебивание (interrupt-resume).** Студент заговорил → capture выставляет
`interrupt` → playback мгновенно глушит TTS. Объект «Ответ» хранит, что уже
озвучено; «продолжай» доигрывает остаток из памяти без вызова LLM. Это снимает
зависания, ради которых переписывалась архитектура. Ложный блип (кашель/шум без
транскрипта) — `interrupt` сбрасывается, ответ молча доозвучивается.

**Распознавание типа реплики — три класса** (ось backchannel / barge-in /
turn-closing):
- *backchannel* («угу», «ага», одиночное «понял») — отсев в `capture.py`, до
  агента не доходит, тьютор говорит дальше;
- *barge-in* (новый вопрос посреди объяснения) → обычная генерация;
- *turn-closing* (comprehension-stop, отказ-продолжать, стоп-команда) →
  завершение без нового вызова LLM.

## 7. Расхождения с первой версией (v1 → v2)

**v1** — сборка тьютора до пересборки: ядро `src/`, унаследованное от
стримингового мультиисточникового агента NetTyan. **v2** — пакет `tutor/`,
переписан с нуля 21.05.2026. Легаси-каталог `src/` удалён.

| Аспект | v1 (`src/`, NetTyan-derived) | v2 (`tutor/`) |
|---|---|---|
| Процессная модель | несколько процессов ОС (главный + STT + TTS) | один процесс, три рабочих потока |
| Обмен состоянием | `multiprocessing.Manager`: общие `ctx_chat`, `tts_queue`, shared state в `ctx_handler` | `queue.Queue` ×2 + `threading.Event` |
| Ядро агента | `CoreAgent` — крупный модуль, `step()`-цикл, FSM | модульный пакет `brain/`, `AgentThread` |
| Управление диалогом | FSM `idle → delivering → qa → farewell` (+ remediation) | без FSM: открытый Q&A + стек ответов |
| UI | Gradio веб-панель (:22229) | консоль, UI нет |
| Возврат после прерывания | повторная обработка, зависания Manager-IPC | объект «Ответ», доозвучка из памяти без LLM |
| Учёт озвученного | маркер `[прервано студентом]` в `ctx_chat` | `Answer.voiced_index` |
| Профиль студента | SQLite `student_profiles.db` (мульти-профиль, weak_blocks, рекомендации) | JSON одиночный профиль (**отключён**, см. раздел 8) |
| Quiz + remediation, скелетный механизм, автоконспект лекции | были реализованы | удалены (pivot 18.05) либо не портированы в v2 |
| Объём ядра | `core_agent.py` ~1500–3607 строк | `brain/` — пакет из ~12 модулей, ~5 тыс. строк суммарно |

**Расхождения, вытекающие из пересборки:**
- v2 **не мультипроцессный** — это инвалидирует формулировку «мультипроцессная
  архитектура» в Положении защиты 1 ВКР;
- v2 **целенаправленно отказался от архитектуры NetTyan** — это инвалидирует
  Научную новизну 3 ВКР («адаптация архитектуры NetTyan»);
- подробный разбор влияния на текст ВКР и варианты переформулировки —
  `../_vkr_tech_state.md`, раздел 6.

> Примечание: смена LLM-стека (Gemma → OpenAI gpt-5.4), STT (`large-v3` →
> `large-v3-turbo-russian`), удаление quiz/skeleton произошли в рамках эволюции
> v1 (16–18.05), до пересборки. Пересборка 21.05 — это смена **архитектуры
> исполнения**, стек моделей она не меняла.

## 8. Известные проблемы и открытые вопросы

**Отключено флагами (баги, требуют починки):**
- `_NESTING_AND_RETURNS_DISABLED=True` (`agent.py`) — вложенность ответов и
  возвраты («вернёмся к…») багуют, ломают обычный Q&A-цикл. Стек работает на
  глубину 1, «вернёмся» вырождается в continue. Заявленная глубина 3 уровня
  фактически недоступна.
- `_PROFILE_DISABLED=True` (`agent.py`) — regex-извлечение имени
  (`extract_student_info`, `meta.py`) систематически ошибается на выходе STT:
  захватывает случайные слова («я понял» → имя «Понял»), мусор попадал в каждый
  системный промпт. Профиль рассчитан на долгосрочное взаимодействие,
  недостижимое при текущей нестабильности; адаптация и так идёт через основную
  LLM. Следствие: персонализация по имени/бэкграунду между сессиями не работает.

**Нестабильность:**
- Тьютор не выдерживает ~часа непрерывной работы — корневая причина не
  локализована. Это и есть основание для отключения профиля (долгосрочное
  взаимодействие сейчас недостижимо).

**Не реализовано:**
- **Фаза 8** — собственный аудио-роутер. Сейчас маршрутизация звука держится на
  ручной матрице VoiceMeeter Banana; `voicemeeterlib` процессу тьютора
  недоступен, авто-роутинг невозможен.
- **Push-to-talk** (режим рации) был заглушкой Фазы 1 и в реальный `capture.py`
  не вошёл — capture всегда слушает (энергетический VAD). Расхождение с
  исходными требованиями.
- **Чувствительность STT** — тихие/быстрые фразы («да», «ага», «понял») не
  пересекают RMS-гейт. План: пороги в env, снижение дефолтов, диагностик замера
  реальных RMS.

**Мелкие дефекты:**
- Фоновая репл’ика («ага» посреди объяснения) на короткое время глушит TTS,
  затем озвучка возобновляется — устранение требует стримингового ASR с
  ожиданием стабильного частичного транскрипта (вне текущего скоупа).

**Git:** ветка `tutor-v2`; коммит `efc1f9a` и правки 22.05 (comprehension-stop,
расширение стоп-логики, отключение профиля) на момент актуализации не запушены.

## 9. Конфигурация

- `.env` — модели, ключи, аудио-устройства, `AUDIO_MODE`, `USE_LOCAL_LLM`,
  `META_BACKEND`. Шаблон — `.env.example`.
- `resources/Prompts/personalities_professor.yml` — персонаж преподавателя.
- `resources/course_config.yml` — placeholders `{COURSE_NAME}` / `{COURSE_TOPIC}`.
- Подготовка своего курса — `docs/RAG_PACKAGE_GUIDE.md`,
  CLI `tools/prepare_rag_package.py`.
- Python 3.10 (строго). Код и комментарии — английский; промпты и персонаж —
  русский.
