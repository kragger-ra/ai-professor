# План демонстрации ИИ-Профессора (Tutor v2 + Board)

Цель — за один сеанс показать весь стек: голосовой Q&A с RAG, доска
(термины/формулы/факты), документы как контекст, комментарии,
переключение курсов, кросс-сессионная память. Хронометраж ~20-25 минут.

## 0. Подготовка (до зрителя)

1. **Окружение**:
   - LM Studio запущен (порт 22227), модель загружена. ИЛИ облако (`USE_LOCAL_LLM=false` + ключ).
   - Vosk-TTS поднимется автоматом из `start_tutor_v2.bat`.
   - PySide6 установлен (`pip install -e .[board]`).
2. **Курсы**: убедиться, что в `courses/` есть как минимум 3 пакета —
   PersonaLab, ПрогрЕстЯз (whitecoding), DSWoK (любой из 3 переводов).
3. **Очистить состояние демо**:
   - `reset_memory.bat` — стирает `student_profile.json` и `session_memory.json`,
     чтобы показать «первый запуск» и потом «второй запуск с памятью».
   - `data/board_events.jsonl` / `board_commands.jsonl` — удалить или оставить,
     борд тейлится с EOF, не страшно.
4. **Документ для демо**: подобрать короткий PDF (~10 страниц) по теме одного
   из курсов — лучше тот, что НЕ входит в его RAG. Это покажет, что
   document_store работает поверх RAG.
5. **Микрофон**: проверить, что выбран правильный вход. `.env` →
   `SOUND_DEVICE_IN`/`SOUND_DEVICE_OUT`. На случай meeting-режима — Banana
   уже сконфигурирован.
6. **Воспроизведение для зрителя**: если онлайн — Контур.Толк/Zoom, аудио
   с CABLE Output, экран — всё окно борда + лог-окно в углу
   (опционально, для технической аудитории).
7. **Чек-лист smoke**:
   - Поздороваться → получить ответ.
   - Один вопрос по курсу → проверить, что доска получает board-item.
   - Сказать «стоп» во время ответа → проверить прерывание.

## 1. Первый запуск + представление (2 мин)

- Запустить `start_tutor_v2.bat`. На экране: окно борда (доска слева, чат
  справа), внизу — индикатор «слушает».
- Зритель видит: чистая доска, статус «Курс: PersonaLab», микрофон активен.
- Сказать: «Здравствуйте, меня зовут Ольга, я backend-разработчик».
- **Ожидание**: профессор приветствует по имени, делает короткое
  введение в курс. (Заметка: если `_PROFILE_DISABLED=True` — поведение будет
  без запоминания имени; для демо стоит на время вернуть `False` через флаг.)

## 2. Базовый Q&A с доской (4 мин)

- Голосом: «Расскажи, что такое PersonaLab». Сразу должен сыграть
  филлер («Так...» / «Минутку.») — **новая фича, см. ниже**.
- Через 1-2 секунды — голосовой ответ + одновременно на доске появляются
  термины как `<strong>Имя</strong> — описание`.
- Голосом: «Покажи формулу метрики». Профессор объясняет, на доску
  выпадает `$$...$$` через KaTeX.
- **Прерывание**: во время длинного абзаца сказать любую короткую фразу
  («понятно»). TTS должен затихнуть ~100мс. Никакого «доводит до конца».
- **Возврат**: «Продолжай». Дочитывает с того же места, БЕЗ нового LLM-вызова
  (показать в логе строку `_handle_continue`).
- **Comprehension-stop**: «Понял, спасибо» → молча завершает объяснение,
  стек чистится. Если зритель технический — открыть `tutor_v2.log` и
  показать ветку `acknowledge -> _stack.clear()`.

## 3. RAG hot-swap (3 мин)

- На тулбаре — pill-switcher «активный курс» (зелёная рамка, первый
  слева). Кликнуть → popup со списком, текущий с галочкой.
- Активировать другой курс (например, ПрогрЕстЯз). В статусбаре имя
  меняется, **тьютор не перезапускается**.
- Голосом: «Что такое канцелярит?» — ответ из нового корпуса.
- Альтернатива (показать вторым шагом): «Загрузи курс DSWoK» — то же
  самое голосом. Хот-своп FAISS-индекса.

## 4. Документы как live-контекст (5 мин)

- Перетащить PDF на окно борда → появляется в доке «Документы» слева.
- Голосом: «Сделай выжимку из этого документа» — ответ ссылается на
  содержимое PDF. (DocumentStore инжектит секцию «Открытые документы
  студента» в системный промпт.)
- Двойной клик по документу → открывается окно `DocumentWindow` с PDF.js
  v3.11 (своя сборка, не нативный плагин).
- Выделить мышью фрагмент → ПКМ → меню:
  - **«Прочитать вслух»** — VOSK озвучит буквально текст выделения, без
    обвёртки контекстом.
  - **«Объяснить смысл»** — в чате появляется intent-чип («— объяснить:
    "фрагмент…"»), ответ ссылается на цитату через
    `Контекст: документ "…". Выделено: "…".`
  - **«Комментарий…»** — модальный диалог с многострочным вводом.
    Сохраняется как `comment_added` в JSONL, текст помечается
    `<mark class="comment-anchor">`. В боковой панели справа — карточка.
  - **«Вставить в чат»** — выделение уходит в поле ввода чата.
- Открыть **«Примечания»** на тулбаре → карточка комментария, клик —
  скролл к подсветке.

## 5. Доска как наглядное (3 мин)

- Голосом: «Объясни механизм attention» (или другой запрос с формулой
  из курса).
- На доске: блочная формула $$Attention(Q,K,V) = softmax(QK^T/\sqrt{d_k})V$$
  через KaTeX, термины Q/K/V вынесены отдельными items.
- 2× ЛКМ на формулу → выделение всего блока нативно. ПКМ →
  «Прочитать формулу» → LLM переводит LaTeX в речь («произведение Q
  и K транспонированное, делённое на корень из d_k...»).
- На любом бабле prof в чате — кнопка ▶. Клик → перечитать ответ
  голосом (через `read_aloud` в IPC).

## 6. Режимы голоса и контроль (3 мин)

- Кнопка слева от поля ввода: **«Запись с правкой»**. Переключает
  `stt_mode` с `open` на `transcribe`. С этого момента речь идёт не в
  LLM, а в поле ввода чата.
- Сказать что-нибудь длинное, дать времени, проверить, что текст
  появляется в QLineEdit. Поправить опечатку руками → Enter → отправить.
- Вернуть «Открытый микрофон». Снова голосовой Q&A.
- Кнопка **mute TTS**: следующий ответ генерируется, в чате виден,
  но без озвучки. Снять mute → следующий ответ снова озвучен.
- Голосом: **«Манера попроще»** → последующий ответ адаптирован под
  упрощённую подачу. **«Подробнее»** → развёрнутый ответ.
- Голосом: **«Пауза»** → STT-капчура встаёт на паузу. **«Продолжай»** —
  снимается.

## 7. Builder RAG-пакета (3 мин)

- Меню «Курсы» → «Подготовить RAG-пакет…» → открывается
  `CourseBuilderDialog`.
- Зона 1: дроп нескольких PDF/DOCX/MD в TreeWidget.
- Зона 2: задать `short_name`, `name`, `topic`, `audience`,
  `teaching_style`, ключевые слова.
- Зона 3: «Собрать». Прогресс-бар + лог. На диске появляется
  `courses/<short_name>/` с `.md` + `course_config.yml`.
- Сразу активировать новый курс из менеджера курсов (док слева).
- Спросить что-то по его содержимому голосом → ответ из свежего корпуса.

## 8. Кросс-сессионная память (финал, 2 мин)

- Закрыть тьютор и борд (`stop_tutor_v2.bat` или красный крест).
- Запустить заново.
- Сказать: «Здравствуйте». Профессор должен:
  - Поздороваться по имени (если профиль был включён в начале).
  - Сослаться на тему прошлой сессии («в прошлый раз мы говорили о ...»)
    — это `session_memory.json` rolling summary.

## 9. Резервные точки (если что-то не работает)

- **Филлер не играет** — продолжать без него, в логе `playback` строки `filler`.
- **Доска пуста** — модель забыла `---BOARD---` маркер. Перезадать вопрос
  с уточнением «и выпиши термин на доску» (не критично).
- **Перебивание не сработало** — `interrupt` остался SET. Сказать «стоп» —
  агент сбрасывает.
- **STT глотает короткие фразы** — это известный открытый вопрос,
  `STT_VAD_THRESHOLD` env. Говорить чуть громче.
- **LM Studio упал** — переключить в `.env` `USE_LOCAL_LLM=false` и
  перезапустить. Облачный fallback (Mistral/Claude/OpenAI) работает с теми
  же промптами.

## 10. Что НЕ показывать (out of scope)

- Lecture-сборка (другая ветка `main`, mode не для индивидуальной работы).
- Tutor v1 (NetTyan-based, мёртв).
- Tests / smoke (это для разработчика, не для зрителя).
- `_PROFILE_DISABLED=True` — открытый баг, лучше предупредить «профиль
  работает, но временно выключен флагом для стабильности».

## Эскалация длительности

Если время поджимает, режется в порядке:
1. Снять Builder (п. 7) — фича глубокая, занимает 3 минуты на демо.
2. Снять Документы (п. 4) — заменить кратким показом drag-drop без меню.
3. Минимум: пп. 1, 2, 3, 5, 8 — голос + доска + RAG + формулы + память.
