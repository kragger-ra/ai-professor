# Отчет о проделанной работе: AI Professor

**Проект:** ИИ-агент-преподаватель для курса PersonaLab Workshop
**Платформа:** ИТМО AI Talent Hub
**Период:** 26 марта — 6 апреля 2026
**Коммитов:** 31
**Итог:** рабочий голосовой ИИ-ассистент с адаптивным поведением

---

## 1. Исходная точка

За основу взят открытый проект NetTyan — автономная ИИ-стримерша для Minecraft (Twitch-бот с голосом, игровыми механиками, фильтрацией чата). Проект содержал ~20 000 строк кода, из которых большая часть была привязана к стриминговому и игровому контексту.

**Задача:** адаптировать архитектуру под образовательный контекст — голосовой ИИ-преподаватель, который слушает студента через микрофон, отвечает голосом, использует материалы курса (RAG) и адаптируется к уровню студента.

---

## 2. Этап 1: Адаптация и очистка (26 марта — 1 апреля)

### Что сделано

- **Персона профессора:** заменена личность стримерши на ИИ-преподавателя с мужским голосом, русским языком, академическим стилем. Три варианта промпта: подробный, краткий, для суммаризации лекций.

- **Голосовой pipeline:** настроена цепочка STT (faster-whisper) -> LLM (Mistral) -> TTS (Fish Speech, затем Piper, затем Vosk). Аудио маршрутизация через VoiceMeeter Banana для работы в Zoom.

- **RAG по курсу:** подключён поиск по материалам 4 лекций через FAISS + Mistral Embeddings. Профессор отвечает с опорой на реальный учебный контент.

- **Удаление стримерского кода:** поэтапно удалены модули Twitch-чата, Minecraft-управления, OBS overlay, фильтрации токсичности, Live2D аватара, донатов. Суммарно удалено ~17 000 строк.

- **Новые модули:** wake word детектор (обращение к профессору), буфер транскрипта, суммаризатор лекций, логирование метрик в SQLite.

### Ключевые решения

- Выбор Mistral Large как основной LLM (баланс скорости и качества для русского языка).
- Отказ от Fish Speech в пользу Vosk-TTS: Fish требовал GPU и имел нестабильное качество русской речи после LoRA-дообучения на 6 минутах данных. Vosk работает на CPU, стабильно и быстро.

## 3. Этап 2: Dual-brain и потоковая архитектура (2-5 апреля)

### Что сделано

- **Dual-brain оркестратор:** маршрутизация запросов между быстрой моделью (Mistral, ~1-2с) и умной (Claude Opus через awstore.cloud API, ~12с). Простые вопросы -> Mistral, сложные -> Claude. Впоследствии упрощено до streaming-only архитектуры.

- **Streaming архитектура (v2):** полный переход на потоковую генерацию. LLM стримит токены -> SentenceBuffer собирает предложения -> каждое предложение сразу уходит в TTS. Время до первого звука: ~2-3с вместо прежних 7-19с.

- **Vosk-TTS сервер:** развернут отдельный HTTP-сервер на базе Vosk (CPU, модель vosk-model-tts-ru-0.9-multi). 5 голосов, выбран male_1. Кеш из ~40 частых фраз для мгновенного воспроизведения.

- **Профили студентов:** SQLite база с именами, уровнем подготовки, интересами, проблемами. Профиль инжектируется в промпт для адаптации стиля объяснений.

- **Meta-agent:** фоновый анализ контекста диалога через Claude Haiku — определяет настроение, тип запроса, off-topic, юмор. Обновляет профиль студента. Работает асинхронно, не блокирует основной ответ.

## 4. Этап 3: Система прерываний и стабилизация (6 апреля)

### Что сделано

- **Система прерываний (3 уровня):**
  1. TTS interrupt — при распознавании речи студента аудио обрывается мгновенно.
  2. LLM stream break — генерация останавливается при появлении нового сообщения.
  3. Stop commands — "стоп", "подождите", "помолчите" -> профессор отвечает "Хорошо, слушаю." без вызова LLM.

- **TTS prefetch:** следующее предложение синтезируется параллельно с воспроизведением текущего. Зазор между предложениями сократился с 300-700мс до ~0мс.

- **Hard timeout для LLM:** стриминг через отдельный поток с очередью. Если Mistral API не отвечает 10 секунд, соединение обрывается и агент восстанавливается (ранее зависал навсегда).

- **Tracking озвученного:** при прерывании в историю сохраняется только то, что профессор реально успел произнести, с пометкой [прервано студентом]. Это позволяет корректно продолжить объяснение.

- **Полная очистка от NetTyan:** удалены все оставшиеся модули (HUD overlay, Minecraft tools, голосовые команды, фильтры токсичности), 19 файлов документации из RAG, хардкоды "NetTyan" в коде. Формат истории для LLM упрощён с игрового ("MINECRAFT CHAT [2m ago]") до читаемого ("[30с назад] Студент: текст").

- **STT коррекции:** автозамена частых ошибок распознавания ("рак" -> "RAG").

- **Детекция тривиальных сообщений:** приветствия, "как дела", "слышите" не дёргают RAG, экономя 0.5-3с на ответе.

## 5. Текущее состояние

### Работает

- Голосовой диалог: студент говорит -> профессор отвечает голосом (E2E ~3-5с).
- RAG по 4 лекциям курса (144 чанка).
- Адаптация под студента (профиль, уровень, интересы).
- Система прерываний (студент может перебить профессора).
- Потоковая генерация с prefetch TTS.
- Стабильное восстановление при сбоях API.

### Архитектура (3 процесса)

```
STT Process (faster-whisper, CUDA)
  -> ctx_chat (shared state)
  -> interrupt TTS при распознавании речи

CoreAgent (main process)
  -> prompt (personality + RAG + profile + history)
  -> stream Mistral -> SentenceBuffer -> tts_queue
  <- interrupt при новом сообщении студента

TTS Process (Vosk-TTS, CPU)
  -> prefetch synthesis
  -> VoiceMeeter -> колонки/Zoom
```

### Количественные показатели

| Метрика | Значение |
|---------|---------|
| Время до первого звука | 3-5с |
| Синтез одного предложения (Vosk) | 200-700мс |
| Зазор между предложениями | ~0мс (prefetch) |
| RAG поиск | 0.5-1с |
| Строк кода удалено (NetTyan) | ~20 000 |
| Строк добавлено (Professor) | ~5 000 |

## 6. Известные ограничения

- **Mistral API периодически зависает** — mitigated через 10с timeout, но ответ теряется. Решение: retry или fallback на локальную модель.
- **STT ошибки** — шум и акцент иногда дают неверную транскрипцию. Частично компенсируется словарем коррекций.
- **Длинные ответы** — профессор иногда генерирует 15-20 предложений. Можно ограничить через max_tokens или pacing.
